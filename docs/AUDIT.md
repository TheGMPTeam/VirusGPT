# Full Audit Report — VirusGPT

Generated by the automated test + analysis pass. Covers: security, structure,
documentation drift, test coverage, and the bugs found + fixed in this cycle.

## 1. Security audit

### 1.1 Path traversal — HARDENED (PASS)
Three user-supplied filename handlers were reviewed for traversal:
- `/api/tts/clone` — `os.path.basename(name)` strips any path; file written into
  `DATA/voices/<name[:60]>.wav`. Safe.
- `/api/generated/{filename}` — `os.path.basename` + `p.relative_to(allowed)`
  raises `ValueError` → 400/404 on escape. Safe.
- `/api/autonomous/artifact?path=` — `p.resolve().relative_to(ROOT/data)` enforces
  confinement; rejects anything outside `data/`. Safe.
- TTS `local:` voice handle — resolved through `DATA/voices`, prefix-checked with
  `startswith(allowed + os.sep)`. Safe.

### 1.2 SSRF / egress (ACCEPTABLE for local tooling)
- Agent `web_search` / `web_fetch` tools hit external URLs (`duckduckgo`, user
  URL). These are sandboxed agent tools that run locally by design (the product is
  an autonomous agent). No server-side secret exfiltration path; tool allowlists
  bound the shell surface.
- `llm`/`tts`/`stt`/`comfyui` clients target configurable LAN URLs (no public
  ingress). Fine for the offline use-case.

### 1.3 Shell sandbox (PASS)
`autonomous/tools.py` shells out only to an **allowlist**
(`ls, cat, echo, python3, node, git, curl, …`); non-allowlisted binaries raise.
File ops are confined to `data/sandbox`. `shell_timeout` defaults to 20s.

### 1.4 Secrets / config (PASS)
- No credentials in the repo. `config.json` holds only URLs/models/timeouts.
- HTTPS is auto-generated with a SAN covering the LAN IP when enabled (so mobile
  Chrome mic works). Key material is written to `data/ssl/` only when `https:true`.

### 1.5 Auth (NONE — by design)
The product is a single-user local/offline agent. There is no auth layer; this is
appropriate for the stated use-case but should be called out in the README so
deployers behind a public IP know to front it with a proxy.

## 2. Architecture & structure

- **Clear layering:** `server.py` (FastAPI routes) → `services/` (Ollama/TTS/STT/
  memory/comfyui clients) → `autonomous/` (orchestrator, runtime, tools, DB) →
  `app/assets/js/` (vanilla ES, no build step).
- **44 API routes** covering chat, TTS, STT, memory, selfdev, gateway, services,
  personas, sessions, DB, and the autonomous A2A engine.
- **No circular imports** observed; `compileall` is clean.
- **Frontend**: 12 focused modules, dependency-injected globals (`API`, `HEALTH`,
  `personas`, `rooms`). No framework, no bundler — easy to reason about, slightly
  chatty over the wire (12 script requests).

## 5. Bugs found & fixed this cycle

1. **[CRITICAL] Per-sentence ▶ buttons played the whole reply.**
   Root cause was *twofold*:
   (a) the shared global `ttsQueue` — clicking any ▶ appended to the queue that
   auto-play had already filled; and
   (b) `splitSentences()` used a regex that matched the **entire** reply as one
   span, so every button was bound to the full text.
   Fix: `playSingle()` (isolated player) + rewritten `splitSentences()` /
   `drainSentences()` splitting strictly on `.!?` boundaries. Verified: clicking
   the 3rd button plays ONLY the 3rd sentence.
2. **[HIGH] `/clear` & `/new` did not mute streaming auto-play.**
   Added per-session `sessionAutoPlay`; both commands set it `false` +
   `stopTTS()`. Speaker toggle re-enables it. Boot seeds it from saved `TTS_ON`.
3. **[MEDIUM] Tool calls never logged in the mission UI.**
   `/api/autonomous/status/{id}` returned event `data` as a raw JSON *string*;
   the frontend guard `if(ev.data && ev.data.tool)` was always false. Server now
   `json.loads`-parses on output; verified live tool.call events carry a dict.
4. **[LOW] Frozen `dist/` bundle is stale** (discovered, not yet rebuilt — see
   Optimization §3.1).
5. **[LOW] `selfdev.py` unused imports** (`Any`, `Dict`) — 2 harmless pyflakes
   warnings; safe to drop.
