## 4. Findings - Not Working / Defects

1. **Settings modal clips services list (confirmed defect).** At 1600x700 the modal box is 546px tall; the Snapchat and Marton Gateway buttons render below the modal border and are unclickable (`elementFromPoint` returns the overlay; clicking them re-fires nothing and the detail pane keeps the previous service). Gmail is the last reachable row. Fix: make `#st-services-list` scrollable (`overflow-y:auto; max-height`) or let the modal grow/scroll.
2. **Service detail staleness is a symptom of (1), not a JS bug.** Direct `renderServiceDetail('snapchat', ...)` works; `/api/services/snapchat|marton/settings|status|tools` all return 200 with correct data. The pane only "shows Gmail" because the click never landed.
3. **Telemetry missions leak as permanently "running".** `/api/missions` held 7 auto-created pseudo-missions ("Agent activity (chat + team tool calls)", "Voice output (TTS synthesis + playback)") running for hours, each streaming TTS events into the feed. I stopped them all via `/api/autonomous/stop` (now `cancelled`). The mission-control telemetry path should not spawn never-ending missions, or should expire them.
4. **Sidebar Stop button does not update mission state text.** `stopMission()` hides the button and POSTs stop, but leaves `#mission-state` showing "running" until the next `loadMissionsList()`. Cosmetic but confusing.
5. **`/api/personas` POST is a blind whole-file overwrite with no validation.** I created a temp persona via API and it replaced the entire array with a single object (the file on disk became one JSON object, not a list). GET then returned a non-list. Recovered by restoring the 4-persona array from the browser's `vg_personas` localStorage backup to `/home/dad/Config/data/virusgpt/personas.json` (verified: GET returns the 4 personas again). Server should validate the payload is a list, and personas should be server-authoritative (the SQLite `personas` table exists but is empty/unused).
6. **Version/updater inconsistent.** `/api/features` says `in_app_updater:true` while `/api/version` reports `version:"dev", commit:"unknown", source_dir:"/Users/Master/virusgpt-mac", updatable:false`. Buildinfo is not baked at Docker build time; status bar shows "dev" and update check returns `not_updatable`. Bake `buildinfo.json` (commit, build time, channel) into the image.
7. **`/api/suggest` quality.** Free-text completion for "tell me about" returned "the blockchain technology, advanced hacking techniques, cybersecurity best practices" - the utility prompt has no topical grounding to the room/persona and leans edgy. For a family-facing app named VirusGPT this is a brand risk; add a safety/grounding line to the suggest prompt.
8. **Dead config entries.** `config.json` defines `services.blender` and `services.ffmpeg` (both disabled, pointing at 10.0.0.120) but `/api/services/blender|ffmpeg|hermes` return "unknown service" - they are not registered in the services registry, so the settings are inert. Hermes appears in `/api/health` but not in the Services panel. Either register them or drop the config keys.
9. **n8n connected but unauthenticated** (`authenticated:false, has_token:false`) - list_workflows ran fine (no key needed for this n8n), but `trigger_workflow`/`create_workflow` will likely 401/403 without an API key. Set the n8n api_key via the Settings password field (it is masked and write-only, which is correct).
10. **Hermes bridge has no token** (`has_token:false`). `ask_hermes` tool + gateway status show `gateway:false, heartbeat:null, crontab:false` - the bridge is reachable but not fully wired.
11. **Chat history leak into personas file.** `personas.json` stores each persona's full `context` array (team-round transcripts). That file is POST-overwritten wholesale (see 5) and grows unbounded. Cap per-persona context (e.g. last 20 turns) server-side.
12. **Sessions table empty by design but confusing.** `/api/sessions` (server) is empty because chat rooms live in browser localStorage (`vg_rooms`); the server sessions CRUD works (create/delete verified) but nothing populates it. Either sync rooms server-side or hide the server sessions concept from the UI.

## 5. Optimization Opportunities

- Settings modal: virtualize/scroll services list; lazy-fetch detail only on click (currently status is fetched per card on open - fine, but the whole list re-renders on every modal open).
- Mission feed polls every 1s (`setInterval(refreshMissionFeed,1000)`) plus per-mission 1.5s status poll; merge into one SSE/websocket when the HUD and mission panel are both active.
- `/api/generate` at 4 steps/256px took 31s end-to-end; the Z-Image Turbo profile is fine, but the 2-image default batch doubles wait - make batch size explicit in the UI.
- `x-tts-rewritten:false` on plain sentences - rewrite cache is working as designed, but rewrite_model `ornith-1.5:9b` cold-load dominates first-request latency; keep it warm or raise `rewrite_timeout` further if first-sentence lag is noticed.
- Memory graph: only 8 concepts; `autolink` and `dream` exist but the store is nearly empty - selfdev `cycle` runs (12 runs logged) yet produced 0-source research entries; consider wiring web_search into selfdev research.
- Frontend cache-busters are consistent (?v=14-19) - keep the discipline; add a CI assertion that index.html asset versions bump when JS changes.
